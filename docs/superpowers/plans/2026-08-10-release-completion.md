# Release Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every remaining source-code and automated-evidence gate between the merged production-readiness release candidate and a deployable institutional pilot, while leaving only genuinely external environment/legal/organizational approvals blocked.

**Architecture:** Keep the existing Next.js 16 + Supabase monolith and the current RBAC/RLS/audit model. Extend release evidence rather than adding business features. Every stage follows RED → minimal fix → GREEN → critical review → regression gate, and no stage weakens tenant isolation, role separation, audit immutability, privacy defaults, or the distinction between internal committee readiness and external SCFHS accreditation.

**Tech Stack:** Next.js 16, TypeScript, React 19, Supabase Postgres/Auth/Storage, Playwright, Vitest, PostgreSQL acceptance tests, GitHub Actions, CodeQL.

## Global Constraints

- No Replit.
- No paid hosting, API, AI, OCR, monitoring, or other chargeable service is activated without explicit user authorization.
- Synthetic test data only.
- External AI stays disabled by default until privacy approval.
- Production secrets never enter source control.
- `SUPABASE_SERVICE_ROLE_KEY` remains server-only.
- Internal committee approval means readiness for submission only and never external accreditation.
- The repository code path remains a monolith; no microservices/Kubernetes/vector database are introduced.
- A stage is not complete until its automated gate passes after the final fix.
